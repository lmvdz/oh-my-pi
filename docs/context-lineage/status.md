## Command surface (§21.6)

Dedicated `/lineage` command (`contextLineage.enabled` gates everything): bare `<task>` compiles a frozen manifest+checkpoint, `status`, `show [id]`, `base <name>|list|inspect|retention|archive|delete <name>`, `benchmark <case-id>|all`, `plan <task>`, and `documentary <local|forge> <authorized-file> :: <task>`. `/fanout` is the canonical parallel-questions command and `/lineage ask` remains its alias. `/wayfinder plan …` binds Campaign tickets to frozen bases. `/context` keeps its original diagnostic meaning.

## Command reference

All surfaces require `contextLineage.enabled: true`; sub-key gates
(`fanout.enabled`, `plans.enabled`, `repositoryContext.enabled`, all default on)
control individual surfaces.

```
/lineage <task>                     Compile a frozen repository manifest + checkpoint
/lineage show [manifest-id]         Inspect selected evidence and omissions (source-free)
/lineage status                     Durable lineage counts (manifests, checkpoints,
                                    plans, named bases, executions, promotions)
/lineage base <name>                Name the most recent checkpoint (idempotent)
/lineage base list                  Active named bases
/lineage base archive <name>        Retire a named base (tombstone, no deletion)
/lineage base inspect <name>        Show versions and checkpoint retention references
/lineage base retention             Show refcounts and logically collectable checkpoints;
                                    session deletion is the physical cleanup boundary
/lineage base delete <name>         Tombstone the reusable name; preserve plan/run provenance
/fanout <q1> | <q2> [| …]           Canonical parallel-questions command
/fanout board                         Open durable Parallel Questions result board (interactive TUI)
/lineage ask <q1> | <q2> [| …]      Parallel questions: staggered no-tools side
                                    requests; answers as sidecar artifacts
/lineage ask --resume <run-id>      Rerun only unfinished stages of a failed run
/lineage candidate board             Open the durable Controlled Candidates board
/lineage candidate rubric <criteria> Store bounded operator evaluation criteria
                                    as a sidecar artifact; use its reference for
                                    candidate review, adjudication, or selection
/lineage answers [run-id]           Per-answer question text, preview, artifact
                                    reference, observed cache status
/lineage promote <run-id> <n>       Promote answer n under its origin leaf
                                    (idempotent, sanitized, digest-only provenance)
/lineage discard <run-id> <n>       Dismiss a completed result without deleting its artifact
/lineage synthesize <run-id>        Synthesize completed named fan-out outputs without rerunning leaves
/lineage diagnostics <run-id>       Inspect durable run, sidecar, and cache-observation metadata
/lineage plan <task>                Generate a manifest-validated repository plan
/lineage plan show [plan-id]        Inspect persisted plan stages, evidence, and assumptions
/lineage plan <task> --current-state-only
                                    Generate with native current-state evidence only
/lineage plan <task> --unguided     Show task-only baseline claims without compiling a manifest
/lineage plan <task> --run          Persist + execute via side requests
/lineage plan --run --execute <plan-id>   Execute an already-persisted plan
/lineage plan --run --resume <run-id>     Rerun only unfinished stages
/lineage benchmark <case-id>        Grounded-vs-unguided comparison (list: bare)
/lineage benchmark all              Run and persist every representative corpus case;
                                    report valid/rejected cases and mean deltas
/lineage documentary <source> <file> :: <task>
                                    Create a plan with one explicit, bounded local or
                                    caller-authorized forge document; no network retrieval
/wayfinder plan <map> <ticket> :: <goal> :: <task>
                                    Bind Campaign ticket to a frozen base and plan
```

## Storage rules

Session records are digest-only (§14.1 MVP storage rule); excerpt bytes live once in the session artifact store referenced by `manifestArtifactId`. Manifest identity is computed over excerpt digests, so stripped and materialized manifests share one identity.
